# WireGuard VPN — the only way into the platform (OKD node)

**Principle:** the platform is reached through the VPN only, from the local network as well as from outside; the local network is **never** reachable from the VPN. Service names point to the server's VPN address (see `../../ingress/`). The VPN is therefore also the **only administration path**: nothing below may cut it.

## Variables

No value from the reference installation is given here: pick your own.

| Variable | Role | Shape |
|---|---|---|
| `${VPN_NETWORK}` | VPN network, a private /24 overlapping neither the local network nor the pod and Service networks | `a.b.c.0/24` |
| `${VPN_SERVER_IP}` | server address on the VPN, also Forgejo's externalIP and the target of DNS names | `a.b.c.1` |
| `${VPN_ADMIN_RANGE}` | range of administration devices: whole node, Forgejo SSH and web | `a.b.c.x-a.b.c.y` |
| `${VPN_PREFIX}`, `${VPN_HOST_MIN}`, `${VPN_HOST_MAX}` | `add-peer.sh` checks: `a.b.c` prefix and assignable last octet | — |
| `${VPN_PORT}` | UDP listening port, forwarded by the upstream router or firewall | — |
| `${LAN_NETWORK}` | the node's local network, never routed into the VPN | — |
| `${GIT_SSH_PORT}`, `${GIT_HTTP_PORT}` | Forgejo ports exposed on the externalIP | — |

Any address outside `${VPN_ADMIN_RANGE}` is a **user** device: HTTP/HTTPS only.

## Files

| File | Role |
|---|---|
| `wg-filter.nft` | template of the `inet sophia_wg` nftables table, independent from OVN-Kubernetes: **administration** → whole node + Forgejo; **users** → 80/443 only; **nothing is forwarded** to the local network, pods or Services, except Forgejo for administration |
| `sophia-wg-filter.service` | loads the filter at boot, before the network, then runs the safeguard |
| `wg-filter-check.sh` | **safeguard**: re-reads the whole ruleset with OVN-Kubernetes' nft; unreadable → deletes the table and raises a journal alert (the cluster comes first, the VPN is **never** cut) |
| `sophia-wg-filter-check.{service,timer}` | re-runs the safeguard 3 min after boot, then every 15 min (OKD updates) |
| `test-nft-ovn.sh` | tests, expression by expression, what OVN's nft can read back (hook-less tables, deleted immediately) |
| `add-peer.sh` | adds a device: name, address, **public key**; checks (format, duplicates, range), profile backup, applied without dropping tunnels |

## 1. Server-side interface

`wg0` is a **kernel** interface managed by **NetworkManager** (profile `/etc/NetworkManager/system-connections/wg0.nmconnection`, mode 600); no extra package is needed on the node.

| Item | Value |
|---|---|
| Address | `${VPN_SERVER_IP}/24` |
| Port | UDP `${VPN_PORT}`, forwarded from the public address (router, firewall) |
| Private key | generated **on the node**, never copied elsewhere; only the public key is given to devices |
| Peers | one per device, `allowed-ips` = its /32 address |
| OKD FORWARD | **DROP** policy: only pod and Service networks are forwarded, the local network is already unreachable |
| Forgejo | externalIP `${VPN_SERVER_IP}` on `${GIT_SSH_PORT}` and `${GIT_HTTP_PORT}`, DNAT to its Service |

Without the filter, **every peer reaches every port of the node** (SSH, cluster API, kubelet, etcd, machine config server, agents API…), and pods and Services directly if it widens its `AllowedIPs`: hence section 3.

**At home**, the tunnel goes through the public address (`Endpoint`): the router must loop the traffic back inside (*hairpin NAT*). Check it with the first device on Wi-Fi.

## 2. Adding a device

1. On the device, **WireGuard** app → *Add a tunnel* → *Create from scratch*: the app **generates the key**; note the displayed **public key** (never the private one).
2. On the node:
   ```bash
   sudo VPN_PREFIX=<a.b.c> VPN_HOST_MIN=<min> VPN_HOST_MAX=<max> \
     ./add-peer.sh <device-name> <VPN address> '<public key>'
   ```
3. On the device, complete the tunnel:
   ```ini
   [Interface]
   PrivateKey = (generated by the app)
   Address = <VPN address>/32
   [Peer]
   PublicKey = <server public key>
   Endpoint = <public address>:${VPN_PORT}
   AllowedIPs = ${VPN_NETWORK}
   PersistentKeepalive = 25
   ```
   No `DNS =`: public DNS already answers `${VPN_SERVER_IP}`. `AllowedIPs` limited to the VPN network: the device's local network is not diverted.
4. iOS: *On-Demand Activation* on Wi-Fi **and** cellular. Android: *Settings → Network → VPN → ⚙ → Always-on VPN*.

Record each device in the peer comment (done by `add-peer.sh`); keep administration addresses for administration workstations only.

## 3. Filter (administrator, on the node)

From an **administration** workstation (the session stays open whatever happens).

```bash
# render the template (EXPLICIT list: the nft code's "$" are left alone)
export VPN_SERVER_IP=… VPN_ADMIN_RANGE=… GIT_SSH_PORT=… GIT_HTTP_PORT=…
envsubst '$VPN_SERVER_IP $VPN_ADMIN_RANGE $GIT_SSH_PORT $GIT_HTTP_PORT' < wg-filter.nft > wg-filter.rendu.nft
grep -n '\${' wg-filter.rendu.nft && echo "⚠ unrendered variable" || echo "fully rendered"
# copy to the node: wg-filter.rendu.nft, wg-filter-check.sh, test-nft-ovn.sh, the three systemd units
# on the node
sudo nft list ruleset > ~/backup-nft-$(date +%Y%m%d).txt          # backup
sudo bash test-nft-ovn.sh                                          # compatibility with OVN's nft
sudo mkdir -p /etc/sophia
sudo install -m 644 wg-filter.rendu.nft /etc/sophia/wg-filter.nft && sudo install -m 755 wg-filter-check.sh /etc/sophia/
sudo nft -c -f /etc/sophia/wg-filter.nft && echo "syntax OK"          # check only, applies nothing
# dead-man switch: the table is dropped in 3 min unless cancelled (the tunnel is untouched)
sudo systemd-run --unit=wg-filter-deadman --on-active=180 /usr/sbin/nft delete table inet sophia_wg
sudo nft -f /etc/sophia/wg-filter.nft && sudo /etc/sophia/wg-filter-check.sh; echo "safeguard=$?"   # must be 0
# → from the administration workstation: NEW SSH session, git fetch, web interface; then:
sudo systemctl stop wg-filter-deadman.timer
sudo install -m 644 sophia-wg-filter.service sophia-wg-filter-check.service sophia-wg-filter-check.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable sophia-wg-filter sophia-wg-filter-check.timer
sudo systemctl restart sophia-wg-filter && sudo systemctl start sophia-wg-filter-check.timer
systemctl is-active sophia-wg-filter; journalctl -t sophia-wg-filter -n 5
```

**Check:**
- administration workstation: SSH, `git fetch` on `${GIT_SSH_PORT}`, web interface;
- user device: the interface answers; a server port other than 80/443 (the agents API, for instance) **does not answer** (the page loads forever), and the counter goes up:
  ```bash
  sudo nft list chain inet sophia_wg input | grep counter
  ```

**Rollback:** `sudo nft delete table inet sophia_wg` (immediate); `sudo systemctl disable --now sophia-wg-filter` (permanent).

Avoid any iptables `FORWARD` rule accepting a forwarded port "for `wg0`": it opens that port to **all** peers as soon as the table is missing. The externalIP DNAT to the Service network is already accepted by OKD.

## 4. Compatibility with OVN-Kubernetes

**Incident (OKD 4.21):** after a power cut, no pod had a network any more (`ovnkube-node` in CrashLoopBackOff, multus timing out), hence no Forgejo, hence nothing depending on it. `ovnkube-controller` re-reads the **whole ruleset** at start with its image's nft (**1.0.9**, versus 1.1.5 on the host) and segfaulted (code 139) on the `inet sophia_wg` table. Before the power cut everything worked because the table had been loaded **after** OVN started: the defect only shows on restart.

**Cause isolated** with `test-nft-ovn.sh` (one test table per expression, **without base chain**, hence no effect on traffic, deleted immediately): **any named set** (`set admins { … }`, `@admins`), with or without intervals, in the `inet` and `ip` families alike. The expression first suspected (`ct original ip daddr`) is readable. Fix: administration range written inline in the rules, same security intent.

**Safeguard:** `wg-filter-check.sh` re-reads the whole ruleset with OVN's nft — `crictl exec` in the `ovn-controller` container when it runs, otherwise `podman` with the last image seen (at node boot CRI-O is not there yet). Codes: 0 readable; 1 unreadable → **table deleted**, `crit` journal alert, unit failed; 2 check impossible → table kept, warning. The choice is deliberate: when in doubt, **the cluster and administrative access come first**, the VPN stays open without filter until fixed; cutting the VPN would deprive the administrator of the only way in.

**After every OKD update** (the nft in the OVN image may change):

```bash
sudo /etc/sophia/wg-filter-check.sh; echo $?          # 0 expected; 2 = OVN unreachable
systemctl status sophia-wg-filter sophia-wg-filter-check.timer
journalctl -t sophia-wg-filter -n 20                  # "ALERTE … SUPPRIMÉE" = filter removed
sudo bash test-nft-ovn.sh                             # on alert: which expressions break
```

If the safeguard removed the table: the cluster runs but **the VPN is no longer filtered** — fix `wg-filter.nft` according to `test-nft-ovn.sh`, then go through section 3 again.

**Rules to keep:** never run `nft flush ruleset`; never touch OVN or OpenShift tables; every nftables test happens in a **hook-less** table deleted right away; every filter load happens under a dead-man switch.
